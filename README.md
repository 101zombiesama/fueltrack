
# FuelTrack

**A food and macro tracker that lets you log meals in natural language.**

FuelTrack is a full-stack web application for people who want to track calorie intake and macronutrients without entering every ingredient into a traditional food diary. Describe what you ate, and the app uses AI to identify foods and portions, estimate calories, protein, carbohydrates, and fat, and save the results to your food log.

**Built for:** individuals monitoring nutrition while cutting, maintaining, or gaining weight, especially those who prefer quick, text-based meal logging.

> **Live deployment:** [fueltrack-six.vercel.app](https://fueltrack-six.vercel.app/) (sign-in required; accounts are administrator-managed after the first account is created).
>
> **Nutrition disclaimer:** Macro and calorie values generated by AI are estimates, not verified measurements. Check packaging or reliable nutritional references when accuracy matters.

## Features

- **Natural-language food logging:** Enter a meal description such as “200 g grilled chicken, rice, and steamed broccoli.” OpenAI parses quantities and estimates nutrients per food item.
- **Multiple meals and dates:** A single description can be separated into breakfast, lunch, dinner, or snacks across different dates.
- **Daily dashboard:** See calorie totals, a goal-progress ring, and protein/carbohydrate/fat progress against your targets.
- **Macro trends:** Explore calorie and macro history over 7, 30, or 90 days, switching between line and bar visualizations and selecting which nutrients to display.
- **Food history:** Navigate previous days, view meals by type, and edit or delete recorded entries.
- **Custom goals:** Configure daily calorie and macro targets, or start from presets for cutting, maintaining, bulking, and higher-protein cutting.
- **Accounts and access control:** Create the first administrator account on a fresh installation; administrators can create additional accounts. Food entries and goals are scoped to each user.
- **Responsive interface:** Built with reusable UI components and light/dark theme support.

## How it works

1. A signed-in user describes one or more meals in the food-entry field.
2. A Next.js API route sends the description and local date/time context to OpenAI.
3. The response is parsed into structured meal entries with estimated calories and macronutrients.
4. Entries are persisted in a libSQL-compatible database and associated with the current user.
5. The dashboard and history screens retrieve entries and calculate totals and trends.

Food parsing is performed on the server so the OpenAI API key is not exposed to browser code. Generated entries are currently saved after parsing; users can edit or remove them afterward.

## Run locally

### Prerequisites

- Node.js 20.9 or later and npm
- An OpenAI API key with access to the model configured in `src/app/api/parse-food/route.ts` (AI requests may incur charges)
- No separate database server for the default local SQLite-file setup

### 1. Clone and install dependencies

```bash
git clone https://github.com/101zombiesama/fueltrack.git
cd fueltrack
npm ci
```

### 2. Configure environment variables

```bash
cp .env.example .env.local
mkdir -p data
```

Set these values in `.env.local`:

```dotenv
OPENAI_API_KEY=your_openai_api_key
AUTH_SECRET=replace_with_a_random_secret_at_least_32_characters
TURSO_DATABASE_URL=file:data/local.db
TURSO_AUTH_TOKEN=
```

Generate a strong session secret with:

```bash
openssl rand -base64 32
```

For a hosted Turso/libSQL database, replace `TURSO_DATABASE_URL` with the hosted `libsql://` URL and set `TURSO_AUTH_TOKEN`. For the local file URL shown above, leave the token empty.

**Never commit `.env.local`, actual API keys, tokens, or a populated database.** The repository includes an `.env.example` template and `.gitignore` rules for `.env*` (except the example) and `/data/`.

### 3. Start the development server

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

On a fresh database, use the **Create the first admin** link on the sign-in screen to set up the initial account. After that, public signup is disabled; an administrator can add users in **Settings → User Management**. The database tables are created automatically when the app first accesses the database.

### 4. Optional checks and production build

```bash
npm run lint
npm run build
npm run start
```

The repository currently exposes lint/build commands but does not define a dedicated automated test script.

## Selected API routes

| Method | Route | Purpose |
| --- | --- | --- |
| `POST` | `/api/parse-food` | Parse and save meals from a natural-language description |
| `GET`, `PATCH`, `DELETE` | `/api/entries` | List, update, or delete the signed-in user's food entries |
| `GET`, `PUT` | `/api/goals` | Retrieve or change daily macro targets |
| `GET` | `/api/summary` | Return daily totals for a date or date range |
| `POST` | `/api/auth/login` | Sign in |
| `GET`, `POST` | `/api/auth/signup` | Check whether first-run signup is open; create the initial admin |
| `GET`, `POST` | `/api/admin/users` | List or create accounts (admin only) |

## Privacy and security notes

- API credentials and the session-signing secret are provided through environment variables, not source code.
- Passwords are hashed with bcryptjs; authenticated sessions use signed JWTs stored in HTTP-only cookies.
- Food entries and goal queries are scoped by authenticated user ID.
- Local data is stored in the ignored `data/` directory when using the sample SQLite-file configuration.
- Do not use real personal or customer data in public example files, screenshots, or commits.
